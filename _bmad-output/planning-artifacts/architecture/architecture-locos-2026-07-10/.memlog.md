- (decision) Stack: Next.js 16 App Router + Postgres (self-hosted on WSL) + local filesystem for image storage + pg-boss for job queue. Why: self-hosted constraint rules out Supabase/R2/Vercel. AI generation calls (Gemini + FASHN) remain third-party.
- (decision) Auth: third-party, phone+OTP, minimal management. Leaning: Clerk. Why: best Next.js App Router DX, phone+OTP first-class, minimal local footprint. VN-SMS caveat: Clerk's default SMS provider may need configuration to route through VN-local provider (eSMS.vn) for reliable delivery; Firebase Auth is the fallback if Clerk's VN SMS is unreliable. To confirm in spike.
- (decision) AI text: Gemini 3.1 Pro for Vietnamese captions. Why: cheapest frontier, acceptable Vietnamese, ~/bin/zsh.10-0.15 per product with image. FASHN v1.6 via fal.ai for on-model image gen (/bin/zsh.075/image, ~10-25s).
- (decision) Job queue: pg-boss (Postgres-native). Why: self-hosted constraint rules out Inngest/Trigger.dev; pg-boss runs in same Node process, no external service, retries + cron built-in. Tens-of-seconds AI generation runs as pg-boss job, status polled by client.
- (decision) Facebook publishing: pages_manage_posts scope, long-lived Page access tokens (~60d), multi-image via published=false uploads + attached_media. Highest-risk unknown: 2026-01-12 Meta blog post about pages_manage_posts change could not be retrieved — verify on Meta changelog before shipping publish path.
- (direction) Design paradigm: hexagonal (ports-and-adapters). Locos-core is the application services + domain entities; adapters wrap Postgres, file storage, SMS provider, AI providers, Facebook Graph API, Clerk, pg-boss. Why: indirection matters when independent builders (the Next.js web app, the background worker, any future script) need to share state and calls without leaking SDKs across boundaries. Layer-pure alternative considered (layered architecture) — rejected because AIs/SMS/FB are unstable providers we want to swap or A/B without touching the core.
